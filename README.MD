## 智能排产+物料齐套看板解决什么问题？

面向制造业，围绕“物料齐套核算、资源预留与规则排产”提供可操作的演示系统。当前交付状态：**已完成中台功能验收；用于业务演示，未完成生产部署验收**。

## 系统架构

```text
浏览器页面 → JavaScript 校验与业务计算 → localStorage
浏览器页面 ← 列表 / 指标 / CSV ← 当前浏览器中的演示记录
```

cockpit 用于 AI 开发过程，不是此系统运行的必需服务。本系统没有因为使用 AI 开发而自动接入运行时大模型。

## 本地运行

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

打开 http://127.0.0.1:8000/index.html 。无需构建或后端依赖，也可直接打开 index.html；建议固定 HTTP 地址，避免浏览器存储来源变化。

## 操作与业务规则

## 操作演示

1. 初始有 4 单、35 吨。DD-001 为紧急订单，10 吨 × 每吨 30 kg 助剂 = 300 kg，库存仅 180 kg，缺 120 kg；满足 1/2 项，齐套率 50%。点击齐套率可查看完整 BOM、需求、供给与缺料。
2. 点击“一键规则排产”。紧急但缺料的 DD-001 被跳过；DD-002 先排入二车间，预留木浆 6000 kg、再生浆 2000 kg、助剂 100 kg。账面库存不变，可用库存下降。
3. DD-003 原先单笔齐套，排入 DD-002 后助剂只剩 80 kg，需求 100 kg，缺 20 kg；齐套率变为 2/3（界面四舍五入显示 67%），不会被重复排入。DD-004 也因再生浆缺 1000 kg 被阻止。
4. 在助剂卡片“补料入库”填写 500 kg。DD-003 立即变为齐套，但不自动排产；再次点击规则排产后进入队列并预留。此时木浆可用为 0 kg。
5. 点击甘特块或队列卡片，同步高亮订单、甘特块、队列，并清除订单筛选以便定位。取消 DD-002 时释放其物料，DD-003 的预留仍保留。修改已排订单前，先取消排产。
6. “新增订单”可设置吨数、交期、优先级、车间、逐项 BOM。填 0 的物料不属于需求项；至少需要一项正耗料。支持新增物料、编辑库存、补料；库存不能改到已预留量以下。
7. 搜索、状态、优先级可组合筛选；CSV 导出当前筛选订单，包含齐套、缺料明细、BOM、计划时间。重置必须确认，取消重置不丢失数据。

## 计算规则与边界

- 单位：订单为吨；BOM 为 kg/吨；库存、预留、需求、缺口均为 kg。需求保留三位小数。
- 需求量 = 订单吨数 × 单吨耗料量。
- 待排供给 = 账面库存 − 所有已排订单的预留；已排供给 = 该订单自己的预留。
- 单项满足条件：供给 ≥ 需求；订单齐套率 = 满足项数 / 需求项数；总齐套率 = 全部订单满足项数之和 / 需求项数之和。
- 未排订单的齐套结果是每单独立试算，不能把多个“可开工”数量理解为能同时开工。实际排产按优先级降序、交期升序、虚构编号升序逐单检查并全量预留，缺料跳过。手动排产也遵守齐套校验。
- “智能”是公开的确定性排序和校验规则，不是 AI 算法；“实时”是用户操作后同步重算，不是后台实时数据。
- 一/二/三车间分别按 2/3/4 吨每小时，车间内串行，不同车间并行。基准时间可改；取消任务后后续任务前移。交期按当日本地时间 24:00 判断。
- 本次实现排产预留，不实现实际生产报工、完工耗料或采购流程；不模拟设备状态、不对接 ERP，不计算班次、换型、停机、损耗。
- 页面没有外部请求；仅当前浏览器 localStorage 保存（键 `development-7-planning-v1`）。不同地址/端口/浏览器之间不共享存档；无多用户或多标签并发协调，不是多人后端。
- 存储被禁用或写入失败时显示提示；清除浏览器数据会丢失存档。
- 手机表格和甘特图可在各自区域横向滑动，390px 宽页面无文档级横向溢出。
